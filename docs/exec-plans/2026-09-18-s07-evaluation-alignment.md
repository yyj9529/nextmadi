# S07 평가 기준 정렬 실행 계획

## Goal

사용자의 실제 질문에 답하고, 제공하지 않은 상황을 만들어내지 않는 결과를 S07의 합격 조건으로 만든다. 평가표, 생성 프롬프트, 응답 계약, 화면이 같은 행동을 요구하도록 맞춘 다음 작은 검증부터 진행한다.

2026-09-18 추가 사용자 합의로 구현을 진행한다. 충돌하는 이전 제안보다 아래 추가 합의가 우선한다. 유료 호출은 단계별 별도 승인 전 실행하지 않는다. 기존 dirty v2와 기존 평가 실행기는 보존하며 새 계약을 버전 분리한다.

## 추가 합의와 실행 순서 (2026-09-18)

1. 짧거나 문법이 서툴러도 의도가 충분하면 바로 분석과 표현 3개를 제공한다.
2. 단어 입력은 AI 호출 전에 `단어가 궁금해요` / `할 말을 만들고 싶어요`를 선택한다. 글자 수나 공백 수만으로 판단하지 않는다. 첫 검사는 보수적 어휘/발화 규칙이며 완전한 의미 판별기가 아니다. 애매한 입력의 최종 방어는 동일 생성 요청의 `needs_context`다.
3. `expressions` / `needs_context` / `word`를 구별한다. 평가와 이유는 표현 위에 표시한다. 적절한 원문은 첫 표현에 유지한다. 모든 표현의 사실과 의도는 같다.
4. 기존 JSONB 저장소와 소유권 검사를 유지한다. 확인 질문·단어 결과에는 표현 저장/TTS/연습 동작을 제공하지 않고 저장 API도 거절한다. 보충은 원문을 편집한 새 요청, 통신 재시도는 같은 키다.
5. 별도 분류 AI, 새로운 API·의존성·DB migration은 기본안에 없다. 사전 기능은 기존 코드에 없다. 기존 생성 모델의 단어 조회와 성공 응답 2회 한도 유지 권장안을 설명한 뒤 사용자의 진행 지시에 따라 구현했다. 확인 질문 무료 제외 정책은 채택하지 않았다. 유료 검증 승인은 별개다.
6. 무료 검증: 입력 대조 사례 → 응답 schema/서비스/BFF → 화면 분기/저장 회귀 → 새 평가기 오류·예산·행동 gate. 기존 기준과 결과는 보존하고 새 평가 버전을 분리한다.
7. 무료 검증 후 소수 유료 검증안의 사례·생성/채점 최대 호출·예상 비용·예산 상한·중단 조건을 제시한다. 승인 전 실제 AI 검증 및 전체 검사는 미실행이다.

## Proposed scoring contract

평가 순서는 아래와 같다. 임계값은 후보 실행 전에 고정한다.

1. **실행/형식:** 요청 성공, 올바른 분기 schema, 모든 필수 필드. 실패하면 `execution_error` 또는 `schema_error`; 내용 점수는 미평가다. 전체 gate는 실패한다.
2. **필수 행동:** R1–R5 중 해당 케이스의 모든 조건을 통과해야 한다. JSON이 맞아도 질문 무시·사실 창작·거절 반전은 실패한다. 자연스러움 평균으로 상쇄하지 않는다. 평가자는 위반 조건과 출력의 근거 구절을 함께 반환하고, 판단 불가를 허용한다. 판단 불가는 사람 확인 전 통과가 아니다.
3. **표현 품질:** expressions 분기에 기존 4개 차원(자연스러움, 정확성, 문화 적절성, 톤)을 적용한다. 현행 수치인 평균 4.0 이상, 차원 평균 3.5 이상, 어느 trial/차원도 2 미만 없음은 낮추지 않는다. clarification에는 영어 발음·톤 점수를 억지로 매기지 않고 질문의 필요성·관련성·최소성을 별도 이진 검사한다.
4. **보고:** 전체 N×trial의 완료/오류/행동실패/판단불가 수와 분기별 분모를 먼저 보여준다. 유효 점수의 평균은 별도 제공한다. 필수 행동은 채택용 전체 실행에서 위반 0건을 요구한다. 이는 고정 테스트에서의 출시 조건이지 실제 사용자 오류율 0% 주장이 아니다.

기존 report-only 초안 지표는 기존 실행기에 보존한다. 새 실행기로의 집계 이식은 미구현이며 새 gate 통과로 대체하지 않는다.

## Implemented decisions and compatibility

- 새 후보 `prompts/s07/v3.md`, schema `s07_analysis_v2`, 평가 계약 `s07-behavior-v2`를 분리했다. 기존 dirty v2, 기존 실행기와 82개 원본은 덮어쓰지 않았다.
- 입력 화면/BFF/백엔드가 같은 어휘·발화 규칙을 사용한다. 단어 선택과 명백한 무의미 입력 안내는 호출 전에 처리한다. 완전한 의미 판별은 규칙으로 보장하지 않으며 생성 응답의 `needs_context`가 두 번째 방어다.
- `expressions`는 평가·이유 아래 표현 3개, `word`는 단어와 뜻, `needs_context`는 꼭 필요한 질문과 입력 수정이다. 뒤 두 분기에 저장/TTS/연습 버튼이 없고 저장 API도 거절한다.
- 기존 JSONB를 사용하고 구버전 결과는 표현 결과로 읽는다. DB migration과 새 유료 서비스·의존성은 없다. 새 결과가 저장된 후 과거 reader만으로 롤백하지 않는다.
- 단어 뜻은 기존 생성 모델을 사용한다. 사전 API가 아니며 정확도 검증은 아직 필요하다.
- 익명 기존 한도(성공 응답 2회/IP/일)를 유지한다. 확인 질문과 단어도 AI 비용이 발생하므로 각각 1회, 이후 보충 성공도 별도 1회다. 호출 전 선택/거절은 0회, 같은 요청 재조회는 추가 0회, 실패는 예약 반환이다. 확인 질문 무료 제외를 원하면 별도 유료 호출 상한 정책이 필요하다.
- 편집은 새 요청 키, 통신 재시도는 같은 키다. 동일 프로세스의 중복 호출은 직렬화한다. 다중 서버의 중복 AI 비용이나 익명 최초 쿠키 유실까지 해결했다고 주장하지 않는다.
