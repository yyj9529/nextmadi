# S07 — Analysis Result

URL: `/save/result/:analysis_request_id`
Authentication: both pre-signup and authenticated allowed. Spring Boot receives
either `session_token` or `user_id` as claims inside `X-Internal-Auth` from the
Next.js BFF.

## Purpose

S07 is the core AI output stage of the product loop. It presents the user's described situation plus 3 generated English expressions, each with tone label, IPA, Korean phonetic guide, and cultural context. Users can play audio, save to library, and (when not signed in) proceed to signup.

This screen is the primary measurement target of the S07 Tier 1 mini eval (ADR-003).

## User Story 1

> As a user who just submitted a Korean situation,
> I want to see 3 natural English expressions with tone, pronunciation, and cultural notes,
> so that I have actionable options for next time.

### Acceptance Criteria

1. **Given** a valid `analysis_request_id` and the user owns the analysis (matched by `user_id` claim if authenticated, or by `session_token` claim if pre-signup),
   **When** the page loads,
   **Then** the screen displays:
   - The original Korean input at the top
   - 3 expression cards (variant_order 1, 2, 3), each showing: English text, tone label, IPA, Korean phonetic guide, pronunciation tip, cultural tip
   - A play button on each card
   - A save button at the bottom (state: "저장하기" if unsaved, "저장됨 ✓" if saved)

2. **Given** the user input contained a tone intent (e.g. "정중하게 표현하고 싶었어요"),
   **When** the LLM generates the variants,
   **Then** the matching tone appears as variant_order 1.

3. **Given** the `analysis_request_id` is invalid or not owned,
   **When** the page tries to load,
   **Then** 404 state with CTA: return to /home (authenticated) or /try (pre-signup).

## User Story 2

> As a user reading the result,
> I want to hear each expression spoken in my coach's voice,
> so that I can practice pronunciation.

### Acceptance Criteria

1. **Given** an expression card is rendered,
   **When** the user taps the play button,
   **Then** `POST /tts/playback` is called with the variant's english_text and the current coach's `tts_voice_id`. Returned signed URL plays via HTML5 Audio.

2. **Given** the user taps play again on the same card within the session,
   **When** the call runs,
   **Then** the response uses cache_status='hit' and no new TTS API charge.

3. **Given** TTS playback fails (timeout or error),
   **When** the failure is detected,
   **Then** toast "음성 재생 실패, 다시 시도해주세요". Card remains usable for save.

## User Story 3

> As an authenticated user,
> I want to save the analysis to my library with one tap,
> so that the expressions are available for review and roleplay.

### Acceptance Criteria

1. **Given** the user is authenticated and the analysis is unsaved,
   **When** the user taps "저장하기",
   **Then** `POST /expressions` with `analysis_request_id` + `selected_variant_order` (default 1) is called. Response: created Expression with embedded variants.

2. **Given** save succeeds,
   **When** the response returns,
   **Then** save button transitions to "저장됨 ✓" (disabled). Toast "📚 책장에 추가했어요". The back-button bookshelf count increments by 1.

3. **Given** the user is pre-signup,
   **When** the user taps "저장하기",
   **Then** the client writes `pending_save` to sessionStorage (analysis_request_id + variant order) and routes to /login.

4. **Given** the user returns from login via the pending-save flow (architecture.md),
   **When** the saved `pending_save` is detected post-auth,
   **Then** save runs automatically without further tap. Toast confirmation. sessionStorage cleared.

5. **Given** the user attempts to save the same `analysis_request_id` twice,
   **When** the second call runs,
   **Then** 409 response with `existing` Expression in body. UI treats as success and shows "저장됨 ✓".

## UI states

| State | Render |
|-------|--------|
| Loading | Skeleton: 3 card placeholders with shimmer |
| Loaded | 3 cards stacked vertically, original Korean above |
| 404 / not found | "찾을 수 없는 결과예요" + return CTA |
| Save in progress | Save button shows spinner, disabled |
| Already saved | Save button "저장됨 ✓", disabled |
| TTS playing | Play button shows pause icon; tap pauses |
| TTS error | Toast, card stays usable |

## Edge cases

- **session_token expired post-signup** — 404 response. User sees apology + CTA to /home.
- **Coach changed between analysis and save** — TTS uses current coach voice. No expectation violation noted in user research.
- **User soft-deletes the saved expression then revisits S07 URL** — analysis_requests row persists, S07 still renders. Save flow detects an existing-but-soft-deleted row and shows a **"복원하기" CTA** rather than auto-saving (owner decision 2026-06-22, option c). Tapping "복원하기" un-deletes the original expression (clears `deleted_at`) so review history is preserved; no duplicate row is created. Frontend wiring requires the Save backend to signal the soft-deleted-restorable state (not just the 409 already-saved case) — tracked as a follow-up on the expression-save backend (#41 area). Until that signal exists, the current 409 → "저장됨 ✓" normalization stands.
- **TTS for variants 2 and 3 not pre-cached** — first play on those cards has latency; design acknowledges; no warming strategy in v1.
