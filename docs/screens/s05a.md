# S05a — Text Input Modal

URL: none — bottom-sheet modal overlay from S04 (`/home`) or S02 (`/try`)
Authentication: required when invoked from S04; not required from S02

## Purpose

Modal for text input as the keyboard alternative to S04's mic-centric flow. Slides up from the bottom, contains an autofocused textarea with a 500-character cap, and submits to the same `/analysis` endpoint as voice input.

This modal also serves as S02's primary input on devices where the user prefers typing.

## User Story 1

> As a user who prefers typing over voice input,
> I want a text input modal that opens quickly,
> so that I can describe a situation without using the mic.

### Acceptance Criteria

1. **Given** the user taps "텍스트로 입력하기" on S04 (or the equivalent on S02),
   **When** the modal opens,
   **Then**:
   - Bottom sheet slides up 250ms with backdrop dim
   - Textarea is autofocused
   - Character counter "0 / 500" visible top-right
   - "분석하기" submit button at the bottom, disabled while empty
   - "취소" or X close button at the top-right corner of the sheet

2. **Given** the user is typing,
   **When** character count changes,
   **Then** counter updates real-time. Counter color: gray under 450, yellow 450-499, red at exactly 500.

3. **Given** character count reaches 500,
   **When** the user attempts to type more,
   **Then** input is blocked at the textarea layer (controlled component caps `value.length`). No further chars accepted. Paste exceeding 500 is truncated to the remaining capacity with a one-time toast "최대 500자까지 가능해요".

4. **Given** valid text exists and the user taps "분석하기",
   **When** submit runs,
   **Then** `POST /analysis` is called (same body shape as S02). Modal stays open with submit button in spinner state until the response arrives. On 201: modal closes, route to `/save/result/{analysis_request_id}` (S07).

5. **Given** the user taps outside the modal or X,
   **When** dismiss runs,
   **Then** modal slides down. If text content exists at dismiss time, it's saved to sessionStorage under `phraselog_draft_input` (5-minute TTL via timestamp). Reopening the modal within 5 minutes restores the draft.

## User Story 2

> As a user with a saved draft from a previous modal close,
> I want to continue where I left off,
> so that I don't lose what I was typing.

### Acceptance Criteria

1. **Given** sessionStorage contains `phraselog_draft_input` with a timestamp under 5 minutes old,
   **When** the modal reopens,
   **Then** textarea is pre-filled with the draft text. Counter reflects the loaded length. Submit button enabled if length > 0.

2. **Given** sessionStorage draft timestamp exceeds 5 minutes,
   **When** the modal reopens,
   **Then** the stale draft is cleared and the modal opens empty.

3. **Given** the user successfully submits,
   **When** the analysis request completes (201),
   **Then** `phraselog_draft_input` is cleared from sessionStorage.

## UI states

| State | Render |
|-------|--------|
| Closed | Not in DOM |
| Opening | Slide-up animation 250ms |
| Open empty | Textarea autofocused, counter "0 / 500", submit disabled |
| Open with draft | Textarea pre-filled, counter shows length, submit enabled |
| Typing valid | Counter updates, submit enabled |
| Approaching cap | Counter yellow at 450+ |
| At cap | Counter red, paste truncated with toast |
| Submitting | Submit button spinner, textarea read-only, close button still enabled (cancels via AbortController) |
| Submit error | Inline toast within modal, modal stays open, textarea editable for retry |
| Closing with draft | Slide-down animation, sessionStorage written |
| Closing without draft | Slide-down animation, no storage write |

## Edge cases

- **Paste of 800 characters when 100 already typed** — input truncated to 400 chars from the paste (so total = 500). Toast "최대 500자까지 가능해요" shown once.
- **Modal closed during in-flight submit** — `AbortController.abort()` cancels the fetch. No analysis_requests row is created server-side because the request handler aborts. sessionStorage draft preserved.
- **Multi-line input** — textarea supports `\n`. Newlines counted as one character each. Server-side `length(input_text) <= 500` CHECK constraint enforces the same.
- **Backspace/delete** — counter decrements normally. No special handling.
- **S04 daily cap reached** — modal trigger button on S04 should be disabled before the modal opens (caller's responsibility), not at modal submit time. **S04 daily cap UI flow TBD in docs/screens/s04.md.**
- **S02 rate-limited (429)** — modal stays open, replaces input area with rate-limit copy + signup CTA (mirrors S02 main page behavior).
