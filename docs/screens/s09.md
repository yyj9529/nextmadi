# S09 — Expression Detail

URL: `/expression/:expression_id`
Authentication: required

## Purpose

Full detail view of a saved expression. Shows the Korean situation plus all three English variants (not just the selected one), with TTS playback on each. Primary actions: start a roleplay session, remove from review queue, soft-delete.

Memo / note attachment was scoped out of v1 (deferred to v1.1+, PRD section 4.3).

## User Story 1

> As a user reviewing a saved expression,
> I want to see all the variant options I had at analysis time,
> so that I can compare tones and choose the most useful one.

### Acceptance Criteria

1. **Given** the user navigates to /expression/{id} (from S04 recent, S08 library, or S12b "원본 표현 보기"),
   **When** the page loads,
   **Then** `GET /expressions/{id}` returns the full expression including all 3 `expression_variants` and the linked `review_card` if not removed from queue.

2. **Given** the page is rendered,
   **When** the user sees it,
   **Then** layout (top to bottom):
   - Header: back button + bookshelf count badge + ⋯ overflow menu (삭제 action)
   - Original Korean situation (full text, not truncated)
   - Three variant cards stacked vertically, the selected variant highlighted; each card shows english_text + IPA + korean_pronunciation + pronunciation_tip + cultural_tip + play button
   - Action buttons row: "롤플레이 시작" (primary) + "복습 큐에서 제거" or "복습 큐에 다시 추가" (toggle based on `removed_from_queue_at`)

3. **Given** the expression is not in the review queue (`removed_from_queue_at IS NOT NULL` or `review_cards` row doesn't exist),
   **When** the action row renders,
   **Then** the toggle button reads "복습 큐에 다시 추가" and tapping calls `POST /review/{review_card_id}/re-add-to-queue` (defined in `openapi.yaml`). Re-entry scheduling matches a newly saved card: `next_review_at = now()`, `current_interval_days = 1` (decided 2026-06-10, PRD Open Question 5).

## User Story 2

> As a user wanting to practice this specific expression in conversation,
> I want a clear roleplay start button,
> so that I move from passive reading to active practice.

### Acceptance Criteria

1. **Given** the user taps "롤플레이 시작",
   **When** the request runs,
   **Then** `POST /practice/sessions` with `expression_id` is called. On 201: route to `/practice/{session_id}` (S12).

2. **Given** the user has hit the daily roleplay limit (2 sessions),
   **When** the call returns 429,
   **Then** UI shows "오늘 롤플레이 한도를 다 썼어요" with reset time, button disabled until tomorrow.

## User Story 3

> As a user who no longer needs an expression,
> I want to remove it cleanly,
> so that my library stays manageable.

### Acceptance Criteria

1. **Given** the user taps the ⋯ overflow menu and selects "삭제",
   **When** the confirmation dialog appears,
   **Then** options: "취소" (dismiss) or "삭제" (commit).

2. **Given** the user confirms delete,
   **When** the request runs,
   **Then** `DELETE /expressions/{id}` soft-deletes (sets `deleted_at = now()`). On 204: route back to /library with toast "삭제됐어요". The expression no longer appears in library, review queue, or bookshelf count.

3. **Given** the user taps "복습 큐에서 제거" instead,
   **When** the request runs,
   **Then** `POST /review/{review_card_id}/remove-from-queue` is called. Expression stays in library but stops appearing in /review. Toast "복습 큐에서 제거했어요". Button label toggles to "복습 큐에 다시 추가".

## UI states

| State | Render |
|-------|--------|
| Loading | Skeleton header + 3 variant card skeletons |
| Loaded, in queue | Full layout, "복습 큐에서 제거" visible |
| Loaded, removed from queue | Full layout, "복습 큐에 다시 추가" visible |
| Loaded, soft-deleted (direct URL access) | 404 state, redirect to /library after 2s |
| Action in progress | Targeted button shows spinner |
| Delete confirmation modal | Centered dialog with 취소 / 삭제 |
| Action error | Toast + button re-enabled for retry |

## Edge cases

- **Direct URL access to a soft-deleted expression** — `GET /expressions/{id}` returns 404 (server filters `deleted_at IS NULL`). UI redirects to /library.
- **Concurrent edit in another tab** — current tab may show stale state (e.g., button shows "복습 큐에서 제거" but it's already removed). Server returns 404 on the action; UI handles gracefully.
- **All 3 variants share the same `tone_label`** (LLM artifact) — UI still renders 3 cards; no special handling.
- **Re-add to review queue** — endpoint not in `openapi.yaml` v1. **Add before W4** as `POST /review/{review_card_id}/restore` or similar, or remove the "다시 추가" button from S09 v1.
