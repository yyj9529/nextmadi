# S01 — Landing

URL: `/`
Authentication: none (public)

## Purpose

Public marketing landing page. Entry point to the try-without-login flow (S02). Shows three random landing examples to communicate what the product does in seconds.

## User Story

> As a first-time visitor,
> I want to immediately understand what PhraseLog does and try it without commitment,
> so that I can verify the product matters to me before signing up.

### Acceptance Criteria

1. **Given** a visitor lands on /,
   **When** the page loads,
   **Then** `GET /landing/examples` returns 3 active examples sampled at random. Each renders as a card showing the Korean situation. Tapping a card pre-fills /try with that example text.

2. **Given** the visitor reads the page,
   **When** they tap the primary CTA "지금 바로 시도해보기",
   **Then** route to `/try` (S02). No pre-filled text.

3. **Given** an authenticated user lands on / (already signed in),
   **When** the page detects the session,
   **Then** auto-redirect to `/home` (S04).

## UI states

| State | Render |
|-------|--------|
| Loading | Skeleton cards (3) |
| Loaded | Hero copy + 3 example cards + primary CTA |
| Loaded zero examples (seed data missing) | Hero copy + CTA only; examples section omitted gracefully |
| Network error on /landing/examples | Hero copy + CTA only; examples section omitted silently (visitor doesn't need this to act) |

## Edge cases

- **CTR-based rotation** is deferred to v1.1+ (PRD section 4.3). v1 ships with `ORDER BY random() LIMIT 3` over all `is_active = true` rows.
- **Visitor returns multiple times** — different random sample each visit. No personalization in v1.
- **Tap-on-example pre-fill** is a small UX win, not critical. **TBD before W4**: whether to skip the pre-fill in v1 and ship a simpler "click → /try empty" interaction first.
