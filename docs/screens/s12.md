# S12 — Guided Roleplay

URL: `/practice/:session_id`
Authentication: required

## Purpose

User practices a saved expression in a multi-turn conversation with their chosen coach. Voice or text input; per-turn feedback shown only when Haiku judges the user's utterance was awkward or grammatically off. Session ends when `planned_turns` is reached or the user exits.

Pipeline (ADR-001, AI_PIPELINE.md): Whisper STT → Sonnet coach response → Haiku turn feedback → OpenAI TTS.

Turn count `planned_turns` is decided by the LLM at session start (range 3–10) based on expression complexity. The user sees a progress indicator but no rationale.

## User Story 1

> As a user starting a roleplay,
> I want the session to open with a clear scenario and the coach's first utterance,
> so that I immediately know what role I'm playing.

### Acceptance Criteria

1. **Given** the user taps "롤플레이 시작" from S04 or S09,
   **When** the request runs,
   **Then** `POST /practice/sessions` with `expression_id` (and optionally `coach_id`) is called. Server creates `practice_sessions` row (status=active), invokes `roleplay_session_init` (Sonnet) which returns `planned_turns` (3–10) and `scenario_setup` (the coach's opening line), then synthesizes TTS for the opening line.

2. **Given** the session is initialized,
   **When** the screen first renders,
   **Then**:
   - The chosen coach's full-body illustration is shown (Mia / David / Sarah)
   - The coach's opening utterance appears as a left-aligned chat bubble
   - TTS auto-plays on render
   - The mic button is enabled, waiting for user input
   - Progress indicator shows "1 / {planned_turns}"

3. **Given** the user has already used 2 sessions today (daily cap),
   **When** they attempt to start another,
   **Then** server returns 429. UI shows "오늘은 2번 다 썼어요. 내일 다시 만나요" with the next reset time. No session row created.

4. **Given** the user has no saved expressions,
   **When** they tap the Roleplay tab from /home,
   **Then** S12 entry is gated — they are routed to S07 or S08 to save an expression first. **TBD before W4**: which destination, and whether to show an inline empty-state CTA instead.

## User Story 2

> As a user mid-conversation,
> I want to speak my response and hear the coach reply,
> so that I practice natural turn-taking.

### Acceptance Criteria

1. **Given** the session is active and waiting for the user's turn,
   **When** the user taps the mic button,
   **Then** recording starts. Tap-to-toggle pattern (PTT 폐기 per ADR-007 sync). Visual: pulsing red mic + waveform.

2. **Given** the user is recording,
   **When** any of the following happens — user taps mic again, 3.5s silence (VAD), 60s max —
   **Then** recording stops. Audio is uploaded to `POST /practice/sessions/{id}/turns` as multipart/form-data. Unlike S02/S04 analysis input, S12 stays one-shot because conversation flow should not pause for transcript editing.

3. **Given** the turn API returns successfully,
   **When** the response includes `user_turn` + `coach_turn` + optional `feedback`,
   **Then** UI sequence (animated):
   - User's transcript appears as a right-aligned purple bubble
   - If `feedback.show_feedback = true`, the feedback card slides up below the user bubble after ~1.5s: `natural_alternative` (English) + `korean_comment` (one short Korean line)
   - The coach utterance appears as a left-aligned bubble
   - Coach TTS auto-plays
   - Mic button re-enabled for next turn

4. **Given** the user prefers text input,
   **When** they tap the keyboard icon next to the mic,
   **Then** the input area switches to a text field. Submit sends the same API call with `application/json` body containing `text_content`.

5. **Given** STT returns empty transcript or confidence below threshold,
   **When** the backend evaluates,
   **Then** the turn is not counted toward `planned_turns`. UI prompts "잘 안 들렸어요. 다시 말해주세요" without consuming a turn slot.

6. **Given** the response indicates `session_status = "completed"` (the final turn just ran),
   **When** the user-visible animation finishes,
   **Then** auto-route to `/practice/{id}/result` after a brief completion indicator.

## User Story 3

> As a user wanting to end early or switch coach,
> I want clear controls,
> so that I'm never trapped in a session.

### Acceptance Criteria

1. **Given** the user taps the X exit button mid-session,
   **When** the confirmation modal appears,
   **Then** options: "계속하기" (dismiss) or "종료" (commit exit).

2. **Given** the user confirms exit,
   **When** the request runs,
   **Then** session `status` updates to `'abandoned'`. `abandoned` sessions do **not** count toward the daily limit of 2 (confirmed in #59; the daily-count query filters `status <> 'abandoned'`). A user who starts and immediately exits does not lose a session slot.

3. **Given** the user taps the coach name dropdown at the top of the screen,
   **When** they select a different coach,
   **Then** a confirm dialog appears ("현재 세션을 끝내고 새 코치와 다시 시작할까요?"). On confirm: current session set to `abandoned`, new session initialized with the new coach.

## UI states

| State | Render |
|-------|--------|
| Initializing | "코치를 깨우는 중..." with coach silhouette and skeleton bubble |
| Active, waiting user turn | Mic button enabled, conversation history scrollable above |
| Recording | Pulsing red mic + live waveform + cancel button |
| Processing (STT → LLM → TTS) | "..." typing indicator in coach bubble area, mic disabled |
| Feedback shown | Yellow card below user bubble with natural alternative + Korean comment |
| Turn error (single-turn failure) | Inline error toast, session continues, turn not consumed |
| Daily limit reached | Blocking modal with reset time, no session render |
| Completed | Brief celebration, auto-route to /result |

## Edge cases

- **Network drops mid-recording** — audio buffered client-side, retry on reconnect. `Idempotency-Key` header on the turn submit prevents double-processing if the original call did succeed.
- **TTS API failure on coach turn** — session continues text-only; coach bubble shown without `audio_url`; turn counted normally.
- **Browser tab inactive during processing** — turn API call continues server-side. On return, `GET /practice/sessions/{id}` re-fetches state, including any turn that completed while away.
- **`text_content` empty after STT** (very low confidence) — treated as no-input; turn not counted; retry prompt.
- **User refreshes mid-session** — `GET /practice/sessions/{id}` returns full state including all turns; UI restores conversation history.
