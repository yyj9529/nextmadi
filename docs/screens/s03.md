# S03 — Login

URL: `/login`
Authentication: transition state (no session before, session after)

## Purpose

NextAuth-handled sign-in flow with three providers (Google, Kakao, email magic-link). After successful auth, routing depends on the user's onboarding state and any pending pre-signup save.

## User Story

> As a visitor ready to sign up or sign in,
> I want a simple choice between trusted providers,
> so that I can authenticate quickly and continue what I was doing.

### Acceptance Criteria

1. **Given** the user enters /login,
   **When** the page loads,
   **Then** three buttons appear in order: Google, Kakao, email magic-link. Order matches PPT v2.2 slide 5 decision (Google primary for general US audience, Kakao for Korean-immigrant target, email as fallback).

2. **Given** the user taps a provider,
   **When** the NextAuth flow runs,
   **Then** redirect to the provider's OAuth consent (or for email: send magic link to entered address with "이메일을 확인해주세요" status screen).

3. **Given** the provider callback returns successfully,
   **When** NextAuth resolves a valid user under the S03 auth policy,
   **Then** route per the following decision:
   - If `users.is_onboarded === false` → `/welcome/coach` (S03b)
   - Else if `sessionStorage.pending_save` exists → return to the S07 saved state
     (`/save/result/{analysis_request_id}`) and auto-save there; **not** `/home`
     (issue #42, S07 US3-AC4). `/home` is only the destination of the 404 apology path
     when the claim fails.
   - Else → `/home` (S04)

4. **Given** the user taps "이용약관" or "개인정보처리방침" links,
   **When** the link is followed,
   **Then** route to `/terms` and `/privacy`, respectively.

## UI states

| State | Render |
|-------|--------|
| Default | Google / Kakao buttons + "이메일로 계속하기" toggle + legal links + intro copy |
| Email form open | Address field + "로그인 링크 받기". Inline validation on empty or malformed input; nothing is submitted |
| Sending | Field and submit disabled, "보내는 중…" |
| Email sent | "이메일을 확인해주세요" + the address it went to + 24h expiry note + "다른 주소로 다시 보내기". Provider buttons are not rendered in this state |
| Send failed | Inline failure message, form stays open. Never the sent state — a "sent" screen over a mail that was never sent is worse than an error |
| OAuth in progress | External redirect; no local state |
| Callback error | "로그인을 완료하지 못했어요. 다시 시도해주세요." banner; provider buttons remain as the retry affordance |
| Expired / reused link (`?error=Verification`) | "링크가 만료됐어요. 아래에서 새 링크를 받아주세요." banner with the email form pre-opened — requesting a new link *is* the retry control |

Expired and already-used links render the same state on purpose. The row is gone in both
cases, so the two are indistinguishable to the app, and the user's next action is the
same either way.

## Edge cases

- **Same email, different OAuth provider** — v1 does not auto-link Google/Kakao accounts by email while the user is signed out. If `provider_email` matches an active `users.email` but `(provider, provider_user_id)` is not already linked, show account-linking guidance: "이미 가입된 계정이에요. 기존 로그인 방법이나 이메일 링크로 로그인해주세요." Email magic-link sign-in is allowed for that address because mailbox ownership is verified. Explicit provider-linking from an authenticated settings flow is not part of S03 v1.
- **Legal docs content** — S03 links use `/terms` and `/privacy`. Before W12 launch, both pages must contain owner-approved Terms of Service and Privacy Policy text. Non-production placeholder pages are acceptable during planning/development only if they clearly say the content is pending; placeholder legal copy is not shippable.
- **Magic-link expired** — expiry is pinned to 24h in the provider config rather than inherited from a default that could change. User sees "링크가 만료됐어요" and can request a new one; the re-request control is the email form, opened automatically when the page loads with that error.
- **OAuth provider rejected** — user sees the standard `callback_error` state with provider-specific guidance.
- **`pending_save` exists but `is_onboarded === false`** — coach selection (S03b) takes priority. After S03b, the save flow resumes by returning to the S07 saved state (not `/home`; issue #42, S07 US3-AC4).
