# S12b — Roleplay Result

URL: `/practice/:session_id/result`
Authentication: required

## Purpose

Structured summary of a completed roleplay session. Generated once by Sonnet (`roleplay_result_v1`) and stored in `practice_sessions.result_json`. Re-visits return the cached result without re-charging.

Four sections: coach encouragement (top), recommended expressions (savable), awkward pairs with natural alternatives, pronunciation focus words.

This screen closes the loop — users save valuable expressions from spontaneous practice back into the library, where they enter the review queue.

## User Story 1

> As a user who just finished a roleplay session,
> I want a structured summary of how I did,
> so that I know what to focus on next.

### Acceptance Criteria

1. **Given** the user arrives at /practice/{id}/result,
   **When** the page loads,
   **Then** `GET /practice/sessions/{id}` returns the session including `result_json` if already generated.
   - If `result_json` is null: `POST /practice/sessions/{id}/result` is called to generate it.
   - If `result_json` exists: render immediately, no additional AI call.

2. **Given** the result is rendered,
   **When** the page is visible,
   **Then** four sections appear top-to-bottom:
   - **Coach encouragement** — short Korean paragraph from coach perspective
   - **추천 표현** (up to 3) — each item: English text + tone label + play button + save button
   - **이렇게도 좋아요** (0–N awkward pairs) — each: "내가 한 말: {user_said}" + "이렇게도 좋아요: {natural_version}" + Korean one-liner comment
   - **발음 포커스** (list of English words) — bare list. If empty: replaced by "발음 깔끔했어요" celebration

3. **Given** the session status is not `'completed'`,
   **When** the page is accessed,
   **Then** server returns 409. UI routes back to /practice/{id} (active session).

4. **Given** the session was `'abandoned'`,
   **When** the page is accessed,
   **Then** result is not generated. UI shows "이 세션은 중간에 종료됐어요" with CTA to /home. `POST /practice/sessions/{id}/result` is not called.

## User Story 2

> As a user reviewing the result,
> I want to save expressions I liked from the conversation,
> so that they enter my library and review queue.

### Acceptance Criteria

1. **Given** a recommended expression card is rendered with a save button,
   **When** the user taps save,
   **Then** `POST /practice/sessions/{id}/save-expression` with `recommended_expression_index` (0-based) is called. Server creates one `expressions` row (`source_type='roleplay_result'`, `practice_session_id` set) + 3 `expression_variants` + one `review_cards` row.

2. **Given** save succeeds,
   **When** the response returns,
   **Then** the save button on that card transitions to "저장됨 ✓" (disabled). Toast: "📚 책장에 추가했어요". Other recommended cards remain savable independently.

3. **Given** the user taps play on a recommended expression,
   **When** the call runs,
   **Then** same TTS playback flow as S07 (`POST /tts/playback` with text + current coach `tts_voice_id`).

4. **Given** save is attempted twice (rapid double-tap or network retry),
   **When** the second call arrives with the same `Idempotency-Key`,
   **Then** server returns the existing expression (no duplicate row). UI treats as success.

## User Story 3

> As a user done reviewing the result,
> I want to return home or revisit the source expression,
> so that I can continue using the app.

### Acceptance Criteria

1. **Given** the user taps "홈으로",
   **When** the route runs,
   **Then** navigate to /home. The bookshelf count badge updates if any expressions were saved this session.

2. **Given** the user taps "원본 표현 보기",
   **When** the route runs,
   **Then** navigate to /expression/{practice_sessions.expression_id} (S09 detail of the source expression).

3. **Given** the source expression has been soft-deleted (`expressions.deleted_at IS NOT NULL`),
   **When** the result page renders,
   **Then** the "원본 표현 보기" CTA is hidden.

## UI states

| State | Render |
|-------|--------|
| Generating result (first visit) | "코치가 정리 중..." with skeleton sections |
| Result loaded | All four sections rendered top-to-bottom |
| Generation timeout / error | Fallback message: "결과를 만들지 못했어요" + retry CTA |
| No awkward pairs | "이렇게도 좋아요" section hidden entirely (no header) |
| No pronunciation focus | "발음 깔끔했어요" with 🎉 instead of word list |
| Saving in progress | Per-card save button shows spinner, disabled |
| Already saved (this card) | "저장됨 ✓", disabled |
| Session abandoned | Stub state, no result generation, return CTA |

## Edge cases

- **Result generation timeout (Sonnet 30s per AI_PIPELINE.md)** — UI shows fallback. Re-tap calls `POST /practice/sessions/{id}/result` again — server retries the LLM call from scratch (no partial state cached).
- **User revisits result much later** — `result_json` is permanent; same content shown forever. No regeneration even if prompt versions change.
- **Source `expressions.id` was soft-deleted between session end and result visit** — `practice_sessions.expression_id` has `ON DELETE SET NULL`. The session row remains; the "원본 표현 보기" CTA is hidden.
- **All recommended expressions saved** — no special celebration state; each card just shows "저장됨 ✓".
- **Recommended expression saved, then soft-deleted via S09** — the saved row is independent of the result_json. Re-visiting S12b does not show "저장됨" anymore because the lookup query filters `deleted_at IS NULL`. Decided by implementation: no "복원하기". Save dedupe matches active rows only (`deleted_at IS NULL`, partial index in `V006__roleplay_result_expression_idempotency.sql`, `PracticeResultService.java`), so re-saving after a soft delete creates a new expression; the result UI has no prior-save state (`RoleplayResultExperience.tsx`).
