# S08 — Library

URL: `/library`
Authentication: required

## Purpose

The user's saved expressions list — the "bookshelf." Time-ordered (most recent first), with keyword search. Cumulative and never auto-pruned (ADR-002). Cards display the Korean situation alongside the selected variant's English text and tone label.

S08 is the user's primary view onto their accumulated practice.

## User Story 1

> As a user with saved expressions,
> I want to browse my library chronologically,
> so that I can revisit what I've collected over time.

### Acceptance Criteria

1. **Given** the user enters /library,
   **When** the page loads,
   **Then** `GET /expressions?limit=20` returns the first batch sorted by `created_at` DESC (most recent first). Cards render with:
   - Korean `original_situation` (truncated at ~80 chars with ellipsis)
   - Selected variant's `english_text` (truncated at ~80 chars)
   - `tone_label` as a small badge
   - Relative time ("3분 전", "어제", "3일 전", "2주 전", etc.)

2. **Given** more results exist beyond the first batch,
   **When** the user scrolls near the bottom (intersection observer trigger),
   **Then** `GET /expressions?limit=20&cursor={next_cursor}` is called. New cards append below existing list. Loading spinner shown at the bottom during fetch.

3. **Given** the user taps a card,
   **When** the tap registers,
   **Then** route to `/expression/{id}` (S09 detail screen).

4. **Given** the library is empty (user has saved zero expressions),
   **When** the page loads with `items.length === 0`,
   **Then** empty state shows:
   - Icon (📚 or similar)
   - "아직 저장한 표현이 없어요"
   - Sub-copy "분석 결과를 저장하면 여기에 모여요"
   - CTA "지금 분석하기" → routes to /home

## User Story 2

> As a user looking for a specific expression I saved earlier,
> I want to search by keyword,
> so that I can find it without scrolling.

### Acceptance Criteria

1. **Given** the search input at the top of S08 is empty,
   **When** the user types a keyword,
   **Then** input is debounced 300ms. After the pause, `GET /expressions?q={keyword}` is called. Results filtered server-side using PostgreSQL `tsvector` index against both `expressions.original_situation` and `expression_variants.english_text` (see `data-model.md` GIN indexes).

2. **Given** the user types Korean text (e.g., "서운"),
   **When** the search runs,
   **Then** matching expressions where `original_situation` contains the term are returned.

3. **Given** the user types English text (e.g., "appreciate"),
   **When** the search runs,
   **Then** matching expressions where any variant's `english_text` contains the term are returned. The list shows the selected variant per card as usual.

4. **Given** the search returns zero results,
   **When** the empty results state renders,
   **Then**:
   - "'{keyword}'에 대한 결과가 없어요"
   - "검색어 지우기" CTA clears the input and reloads the full chronological list

5. **Given** the search input is cleared (X icon tapped or empty),
   **When** the change fires,
   **Then** the unfiltered list reloads (same as initial /library load).

## UI states

| State | Render |
|-------|--------|
| Loading first batch | 5 card skeletons with shimmer |
| Loaded with results | Cards list + bookshelf count in header ("📚 47권") |
| Empty (no saves ever) | Empty state with home CTA |
| Searching | Spinner inside search input |
| Search no results | "검색 결과 없어요" + clear CTA |
| Loading more (pagination) | Bottom spinner under last card |
| End of list reached | No spinner; subtle "다 봤어요" text or just no further fetch |
| Network error initial load | Full-page retry CTA |
| Network error pagination | Bottom inline retry CTA, existing cards retained |

## Edge cases

- **A card in the current view was soft-deleted in another tab** — server-side query filters `expressions.deleted_at IS NULL`. On the current tab the card stays visible until the user refreshes or scrolls past and returns. Acceptable for v1 (no real-time invalidation).
- **Search keyword > 100 chars** — server truncates the `q` parameter to 100 chars before tsvector matching. Most realistic searches are short.
- **Mixed Korean + English keyword** — `tsvector` with `'simple'` config (per `data-model.md`) tokenizes by whitespace, matches both. No special handling needed.
- **Pagination cursor invalidated by new save mid-scroll** — extremely unlikely (user is browsing not saving); a refresh resolves. Cursor is opaque to client.
- **User has many expressions (e.g., 500+)** — the list is rendered virtualized via `react-window` or similar. **Virtualization library choice TBD in implementation phase.**
- **Card tap during search** — navigating to S09 detail works the same; back navigation from S09 returns to /library with search state preserved via URL query string (`/library?q=keyword`).
