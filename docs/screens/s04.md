# S04 — Home

URL: `/home`
Authentication: required

## Purpose

The main authenticated dashboard. Multiple entry points to the product loop: new analysis (mic or text), roleplay, library, review. Aggregates state for fast first paint via a single API call.

## User Story 1

> As a returning user,
> I want to see at a glance what's available to me today,
> so that I can immediately pick where to go.

### Acceptance Criteria

1. **Given** the user enters /home,
   **When** the page loads,
   **Then** `GET /home/dashboard` returns in one round trip:
   - User profile (name, selected coach)
   - Time-appropriate coach greeting card
   - Bookshelf count (`expressions` where `deleted_at IS NULL`)
   - 2 most recent expressions (compact projection)
   - Due review count
   - Today's roleplay session count and the daily limit (2)

2. **Given** the dashboard is rendered,
   **When** the user sees it,
   **Then** UI layout (top to bottom):
   - Coach greeting card with time-of-day variant (06-12 morning, 12-18 day, 18-22 evening, 22-06 late)
   - Hero mic button + "텍스트로 입력하기" alternative below it
   - "최근 저장한 표현" row showing 2 cards + "전체 보기" link to S08
   - Bottom navigation (홈 / 롤플레이 / 기록 / 복습) with due-review badge on 복습 tab

3. **Given** the user taps the mic button,
   **When** voice recording starts,
   **Then** same flow as S02 voice input (recording → STT → `POST /analysis` → /save/result/:id).

4. **Given** the user taps "텍스트로 입력하기",
   **When** the modal opens,
   **Then** S05a text input modal appears.

5. **Given** the user has reached today's roleplay limit (2 sessions),
   **When** the Roleplay tab in bottom nav is rendered,
   **Then** tab label includes "2/2" and tapping shows a blocked state with reset time. **Blocked UI design TBD before W4** — inline message vs modal.

## User Story 2

> As a user who has used the app before,
> I want quick access to my history,
> so that I can resume practice without searching.

### Acceptance Criteria

1. **Given** "최근 저장한 표현" row renders,
   **When** the user taps a card,
   **Then** route to `/expression/{id}` (S09).

2. **Given** the user taps "전체 보기" link,
   **When** the tap fires,
   **Then** route to `/library` (S08).

3. **Given** the bookshelf count badge appears in the header,
   **When** the user taps it,
   **Then** route to `/library` (same as "전체 보기").

4. **Given** due reviews exist,
   **When** the user taps the 복습 tab or any "복습 시작" CTA,
   **Then** route to `/review` (S10).

## UI states

| State | Render |
|-------|--------|
| Loading dashboard | Skeleton sections (coach greeting, mic, recent row) |
| Loaded with data | Full dashboard as described |
| Empty (no saved expressions yet) | Coach greeting + mic + "분석하면 여기에 모여요" placeholder |
| Network error on dashboard | Full-page retry CTA |
| Roleplay daily cap reached | Roleplay tab shows "2/2", taps blocked with reset time |
| Mic recording | Same mic state machine as S02 voice |

## Edge cases

- **`is_onboarded === false`** — should never reach S04; S03 routing prevents. If reached (bug), middleware redirects to /welcome/coach.
- **`selected_coach_id` somehow null after onboarding** — fallback greeting "안녕하세요!" without coach name. Log warning.
- **Bookshelf milestone celebrations (10/25/50/100/200/500 권)** — PPT v2.2 mentions milestone visualizations. **Milestone trigger and animation TBD before W4** in s04.md follow-up.
- **Time-of-day greeting boundary** — uses user's browser local time. No server-side enforcement.
- **`recent_expressions` array shorter than 2** (new user with 0 or 1 saves) — row renders with what's available; empty placeholder for the missing slot.
