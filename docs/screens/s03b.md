# S03b — Coach Selection

URL: `/welcome/coach`
Authentication: required

## Purpose

One-time coach selection for newly authenticated users. Three coaches (Mia, David, Sarah) are presented as comparable cards; the user picks one explicitly. AI auto-matching was rejected in favor of direct user selection (PRD section 5.9, PPT v2.2 slide 19).

After selection, `users.is_onboarded` becomes true. The coach can still be changed later via S11 settings.

## User Story

> As a newly signed-up user,
> I want to choose my coach personality from a clear comparison,
> so that the practice voice feels right for me from the start.

### Acceptance Criteria

1. **Given** the user arrives at /welcome/coach (typically after S03 OAuth callback when `is_onboarded === false`),
   **When** the page loads,
   **Then** `GET /coaches` returns 3 coach profiles. Each renders as a comparison card showing:
   - Coach name + sub-label (Mia 친절한 코치 / David 근엄한 코치 / Sarah 프로페셔널 코치)
   - Persona summary (one paragraph)
   - Sample greeting line in their tone
   - A "Play voice sample" button (optional — uses `POST /tts/playback` with a fixed sample phrase). **Voice sample TBD (open)**: not shipped as of 2026-09 — `src/components/app/CoachCards.tsx` renders a static text sample line only; whether to add it in v1 is undecided.

2. **Given** the user taps a coach card "선택하기" button,
   **When** the request runs,
   **Then** `PATCH /me` is called with `{ selected_coach_id, is_onboarded: true }`. On success: route to `/home` (S04), or resume pending save flow if applicable.

3. **Given** the user attempts to access any other authenticated route before selecting,
   **When** the route guard fires (NextAuth middleware checking `is_onboarded`),
   **Then** redirect back to /welcome/coach. The user cannot bypass this step in v1.

4. **Given** the user has already completed S03b previously and revisits the URL directly,
   **When** the page is accessed with `is_onboarded === true`,
   **Then** auto-redirect to /home. (Coach changes happen via S11, not S03b.)

## UI states

| State | Render |
|-------|--------|
| Loading | 3 card skeletons |
| Loaded | 3 cards stacked vertically (or horizontal carousel on wider viewports) + intro copy |
| Selecting (PATCH in progress) | Selected card highlighted, others dimmed, spinner on selected |
| Selection error | Toast "선택을 저장하지 못했어요" + retry; cards interactive again |

## Edge cases

- **Three coaches not yet seeded in DB** — would block onboarding entirely. Seed `coach_profiles` rows are part of Flyway migration `V_seed_coaches.sql`. Production deploy must run seed before opening signups.
- **User force-quits during PATCH** — `is_onboarded` remains false; next session lands back here. No partial state issue.
- **Pending save exists alongside `is_onboarded === false`** — S03b runs first. After PATCH success, the pending save flow continues (architecture.md).
- **Voice samples increase TTS cost on this screen** — if shipped, three TTS calls per visitor. Mitigated by `tts_audio_cache` (same coach + same sample text = cache hits after the first visitor). **Sample voice clip text TBD (open; depends on the voice-sample decision above).**
