# 시뮬레이션 분기의 화면과 입력값 일관성

## 증상

실패 사례 화면은 소유권 불일치·중복 제출인데 오른쪽 데이터에는 정상 사례의 같은 소유자·isSubmitting=false가 남았다. 숫자 입력의 change에만 의존한 문법 실험은 blur 전에 예측 확인 시 이전 값을 사용했다.

## 근본 원인

기본 정상 이벤트를 재사용하면서 실패 조건을 화면 문구에만 적용했다. 입력 상태를 change에서만 갱신하여 화면 값과 계산 값이 잠시 분리되었다.

## 올바른 방법

사례별 유효 입력을 공통 상태에서 생성하고 화면·데이터가 함께 사용한다. 계산에 쓰는 숫자는 input에서 반영하고 경계값을 검증한다. 실제 실행과 설명 모델은 구분한다.

## 자동화 후보

분기별 입력/출력 불변식과 UI에서 조건을 바꾼 뒤 예측하는 시나리오를 검사한다. 이번에는 독립 시제품의 check.cjs에서 중복 제출·소유권·빈 입력·Stream 경계값을 검사했다.
