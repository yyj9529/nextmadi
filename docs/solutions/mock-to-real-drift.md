# 목 데이터 ↔ 실데이터 계약 드리프트

## 증상

S01 메인화면에서 예시 카드를 클릭해도 S02(`/try`) textarea에 문장이 자동입력되지
않음. 두 화면 다 "구현 완료"로 티켓이 닫혀 있었다.

## 근본 원인

데이터 소스 불일치.

- S01은 티켓 #32/#33에서 `GET /landing/examples` 실데이터로 전환 → 링크에 실제 DB id를
  실어 `/try?example={id}`로 이동
- S02는 그 id를 여전히 하드코딩 목 데이터 `mockLandingExamples`에서 조회.
  목 id와 실 id가 절대 일치하지 않아 항상 `undefined` → prefill = `""`

prefill은 이미 닫힌 #33(S01)과 #35(S02) **양쪽의 요구사항**이었는데 어긋난 채로 둘 다
닫혔다. 전담 티켓이 없어서 아무도 양쪽을 대조하지 않았다. 회귀는 #32의 실데이터 전환이
노출시켰을 뿐, 원인은 그 전부터 있었다.

## 함께 나온 실수

디버깅 중 상수 재사용을 위해 `"use client"` 모듈에서 `MAX_INPUT_LENGTH`를 export하고
서버 컴포넌트에서 import했다. **서버가 client 모듈의 export를 import하면 값이 아니라
client 참조 프록시가 온다.** `slice(0, NaN)`이 되어 prefill이 빈 문자열. RSC payload를
curl로 뜯어보고서야 잡았다.

## 올바른 방법

- 한 기능이 두 화면에 걸치면, 화면별 티켓이 닫힐 때 **연결점을 실제로 눌러본다.**
  각 화면의 단위 검증만으로는 계약 드리프트가 안 잡힌다
- 목 데이터를 실 API로 교체할 때는 그 데이터를 **소비하는 쪽 전부**를 grep해서 확인
- 서버 컴포넌트는 `"use client"` 모듈에서 값(상수)을 import하지 않는다.
  공유 상수는 별도의 서버/클라이언트 중립 모듈에 둔다
- 화면 간 전달은 조회용 id보다 값 자체가 안전할 때가 있다. 이 건은 매 방문 무작위
  3개(no-store)라 id 재조회가 구조적으로 불가능해 문장 자체를 전달하는 쪽으로 바꿨다

## 자동화 후보

재발 2회. 아직 3회 미만이므로 자동화 없이 노트만 둔다.

- 후보: `mock*` 접두 데이터 모듈을 import하는 프로덕션 경로를 lint로 표시
- 후보: 화면 간 flow 스모크 테스트 (S01 클릭 → S02 prefill)
