# 초록불이 아무것도 증명하지 않을 때

이 계열이 가장 위험하다. 실패가 실패처럼 보이지 않고 **성공처럼 보인다.**

## 증상

- eval 전 케이스가 정확히 1.00점 → API 크레딧 부족으로 호출이 실패했는데 예외 핸들러가
  최저점 1을 채워 넣고 있었다. "낮은 점수"로 보였지 "호출 안 됨"으로 보이지 않았다
  (`20260610_1104`)
- CI Backend 잡 초록불. 그런데 로그에 `docker`/`testcontainers`/`postgres` 검색 결과
  0건 — 컨테이너 테스트가 실제로 돌았는지 증명할 수 없었다 (`20260802_0830`)
- 로컬 통합 테스트 9개가 Docker 부재로 조용히 스킵. `BUILD SUCCESSFUL`은 그대로 떴다
- 리팩터링 스크립트의 import 주입 단계가 **조용히 실패**해 97개 컴파일 에러로 뒤늦게
  드러남 (`20260619_1315`)
- `@ConditionalOnBean` 조건이 항상 false여서 빈이 조용히 생성되지 않음 → 런타임 500
- 회귀 방어 테스트가 **설정 객체의 모양**만 봤다. 모양은 그대로인데 런타임 경로가 깨져
  Google/Kakao 로그인이 전부 죽어 있었고 스위트는 초록불이었다. 게다가 다른 테스트는 그
  깨진 동작(어댑터가 던지는 것)을 정답으로 고정해두고 있었다 (`20260828`)
- 새로 쓴 테스트에서 `await expect(...).rejects`의 `await`를 빼먹었다. reject 여부를 실제로
  검사하지 않는데 초록불이 뜬다 — "테스트 없음"이 "가짜 테스트 있음"으로 바뀔 뻔했다
  (`20260828`)
- `./gradlew test build`가 `Task :build UP-TO-DATE`로 20초 만에 `BUILD SUCCESSFUL`.
  직전 실행(113 skipped)의 결과를 그대로 재사용한 것이라 테스트가 한 건도 돌지 않았다
  (`20260828`)

## 근본 원인

두 가지가 겹친다.

1. **예외 핸들러가 실패를 유효한 값으로 변환한다.** `except: scores = 1` 같은 fallback은
   실패 신호를 정상 데이터 형태로 바꿔버린다
2. **집계 출력이 없으면 통과의 의미가 확정되지 않는다.** `BUILD SUCCESSFUL`은 "무엇이
   통과했는가"를 말해주지 않는다. 조건부 skip이 있는 스위트에서는 특히

## 올바른 방법

- 실패 경로는 값을 만들어내지 말고 **구별 가능한 표식**을 남긴다 (null, error 필드,
  명시적 예외). 점수 자리에 최저점을 채우지 않는다
- 초록불을 봤으면 "무엇이 실행됐는지" 한 줄이라도 확인한다. 확인할 수단이 없으면
  그 수단을 먼저 만든다
- **테스트 개수를 눈으로 확인한다.** `BUILD SUCCESSFUL`이 아니라 `N tests, N passed,
  0 skipped`를 본다. 개수가 안 나오면 실행되지 않은 것이다
- **재검증은 `cleanTest`로 강제한다.** Gradle은 입력이 안 바뀌면 이전 실행 결과를 재사용하고,
  그 이전 실행이 나쁜 결과였어도 똑같이 재사용한다
- **새 테스트는 대상 코드를 일부러 깨뜨려 빨간불을 확인한 뒤 커밋한다.** 초록불은 테스트가
  무엇을 검사하는지 말해주지 않는다. 비동기 단언은 특히 — `await`이 빠지면 아무것도 검사하지
  않으면서 통과한다
- **회귀 방어는 설정이 아니라 실행 경로를 검사한다.** 설정 객체의 모양이 같아도 런타임은
  깨질 수 있다 (`docs/solutions/library-call-sites-unread.md`)
- 스킵된 테스트는 스킵으로 보여야 한다. `build.gradle`의
  `testLogging { events 'skipped','failed' }` + `afterSuite` 집계가 이 역할을 한다
  (커밋 `5a30fda`, 2026-08-02 도입)
- fail-fast의 대가를 인식한다: 포맷 검사가 먼저 실패하면 그 뒤 컴파일 에러 15개가
  가려진다. 표면 메시지를 통과시킨 뒤 전체를 다시 돌린다

## 자동화 후보

부분 반영 상태 (testLogging 집계는 백엔드에만).

- eval 스크립트의 예외 fallback 제거 또는 `status: error` 필드 분리 — `eval/s07-analysis/`
- CI에서 Docker 필요 테스트가 0건 실행되면 잡 실패 처리
