# spotless 포맷 위반으로 CI 실패

## 증상

PR을 올리면 Backend CI가 `spotlessJavaCheck`에서 빨간불. 로직 테스트는 전부 통과인데
포맷만으로 잡이 실패한다. 수정 커밋 하나를 더 쌓고 다시 기다린다.

## 근본 원인

로컬 검증을 `./gradlew test`까지만 하고 `spotlessCheck`를 빼먹는다. spotless는 수동
편집(sed 치환, 손으로 붙인 패치, 리뷰 반영) 직후에 거의 항상 깨진다. Java 파일을
직접 만진 세션에서는 예외 없이 재발했다.

한 번은 더 나빴다: 포맷 검사가 먼저 실패하면서 그 뒤의 **컴파일 에러 15개가 가려졌다**
(`20260617_1250`). fail-fast가 진짜 원인을 숨긴 사례.

## 올바른 방법

백엔드 코드를 한 줄이라도 만졌으면 push 전에:

```bash
cd backend && ./gradlew spotlessApply && ./gradlew spotlessCheck test build
```

`spotlessApply`를 먼저 돌리고 `spotlessCheck`로 확인한다. `test`만 돌린 결과는 CI
통과를 예측하지 못한다.

## 자동화 후보

재발 13회 — 규칙상 이미 자동화되었어야 한다.

- pre-push 훅에서 `backend/**/*.java` 변경 감지 시 `spotlessCheck` 실행, 실패하면 push 차단
- 또는 PreToolUse(Bash) 훅에서 `git push` 명령을 가로채 동일 검사
- 훅 실패 메시지에 `spotlessApply` 명령을 그대로 출력해 복구 비용을 0으로
