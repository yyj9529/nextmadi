# 생성 파일 churn을 커밋에 섞음

## 증상

`bun run build` 또는 `next build`를 돌리면 `next-env.d.ts`가 변경된 상태로 남는다.
스테이징할 때 같이 딸려 들어가고, 리뷰어는 티켓과 무관한 diff를 보게 된다.
(이 대장을 쓰는 시점에도 작업 트리에 `M next-env.d.ts`가 떠 있었다.)

## 근본 원인

`next-env.d.ts`는 Next가 자동 생성하는 파일이고 **dev 모드와 build 모드에서 내용이
다르다.** dev 서버를 띄운 뒤 build를 돌리면 라우트 타입 참조가 바뀌면서 매번 변한다.
git이 추적 중이라 변경이 그대로 노출된다.

매번 "revert 했다"고 dev-log에 적혔다 — 즉 사람이 매번 손으로 되돌리고 있었다.
그게 6번 반복됐다.

## 올바른 방법

- build 후 `git status`에 `next-env.d.ts`만 떠 있으면 `git restore next-env.d.ts`
- 티켓 스테이징은 파일을 명시적으로 나열한다. `git add -A`를 쓰지 않는다
- 이 파일이 의도적으로 바뀌어야 하는 경우(Next 버전 업 등)는 별도 커밋으로 분리

## 자동화 후보

재발 6회.

- PreToolUse(Bash) 훅: `git add` / `git commit` 명령에 `next-env.d.ts`가 포함되면 차단
- 더 단순한 대안: `.gitignore`에 넣고 추적 해제. 단 Next 공식 권장은 커밋 유지이므로
  이 변경은 오너 결정 사항 — 결정 전까지는 훅 쪽이 안전
